\chapter{Avant-propos}

Présenter un papier de recherche n'est pas réciter son résumé. C'est
reconstruire sa chaîne de preuve :

\begin{enumerate}
  \item quelle affirmation est faite ;
  \item quel mécanisme la soutient ;
  \item quelle expérience la mesure ;
  \item quelle limite l'auteur reconnaît ;
  \item quelle limite il ne voit pas.
\end{enumerate}

Votre talk doit rendre cette chaîne visible. Une démonstration qui marche
mais qui ne prouve rien est une animation, pas une preuve.

\chapter{Exercise 00}
\extitle{Carte des affirmations}
\turnindir{ex00}
\exnumber{00}
\exfiles{paper-map.md}
\exauthorize{un éditeur de texte, le papier, le dépôt compagnon}
\makeheaderfiles

Dans \texttt{paper-map.md}, listez dix affirmations du papier. Pour chacune :

\begin{enumerate}
  \item la citation ou la section ;
  \item le mécanisme qui la soutient ;
  \item la preuve expérimentale ;
  \item le niveau de confiance (fort, moyen, faible) ;
  \item une limite ou une question ouverte.
\end{enumerate}

Séparez clairement :

\begin{itemize}
  \item ce qui est \emph{démontré} ;
  \item ce qui est \emph{observé} sur le corpus ;
  \item ce qui est \emph{extrapolé}.
\end{itemize}

Incluez au moins une affirmation sur le patch gap (Project Zero,
OtterRoot, Samsung Internet) et une sur un correctif incomplet
(Dark Elevator et CVE-2026-66804).

\hint{Le papier est honnête sur plusieurs limites : faux positifs, faux
négatifs, classifieur circulaire, absence de validation
out-of-distribution. Votre carte doit les faire apparaître.}

\chapter{Exercise 01}
\extitle{Reproduire le classifieur}
\turnindir{ex01}
\exnumber{01}
\exfiles{repro.md repro/}
\exauthorize{Python 3, le dépôt compagnon, un éditeur de texte}
\makeheaderfiles

Reproduisez une partie de l'évaluation du classifieur sur un petit
échantillon local. Ne prétendez pas reproduire les 62 CVE si vous n'avez
pas les données complètes.

\subsection*{Mission}

Dans \texttt{repro/} :

\begin{enumerate}
  \item un script qui charge un petit CSV ;
  \item une baseline naïve ;
  \item une version inspirée du classifieur du papier ;
  \item une matrice de confusion ;
  \item un fichier de résultats reproductibles.
\end{enumerate}

Dans \texttt{repro.md}, expliquez :

\begin{itemize}
  \item les données utilisées et leur provenance ;
  \item la différence entre précision, rappel et F1 ;
  \item pourquoi le résultat du papier peut être optimiste ;
  \item ce que vous n'avez pas pu reproduire.
\end{itemize}

\chapter{Exercise 02}
\extitle{Démonstration de variant hunt}
\turnindir{ex02}
\exnumber{02}
\exfiles{demo.md demo/}
\exauthorize{git, grep, un éditeur de texte}
\makeheaderfiles

Préparez une démonstration de dix minutes qui montre la boucle d'audit sur
un petit cas. La démonstration doit être déterministe : pas de réseau, pas
de cible réelle, pas de timing fragile.

\subsection*{Mission}

Dans \texttt{demo/} :

\begin{itemize}
  \item un petit dépôt ou une copie de fichiers ;
  \item un script qui extrait les lignes ajoutées ;
  \item une requête qui trouve un twin ;
  \item une sortie attendue, versionnée.
\end{itemize}

Dans \texttt{demo.md}, écrivez le storyboard :

\begin{enumerate}
  \item ce que le public voit à l'écran ;
  \item ce que vous dites ;
  \item la preuve produite ;
  \item le faux positif que vous montrez volontairement ;
  \item la conclusion.
\end{enumerate}

\chapter{Exercise 03}
\extitle{Talk et slides}
\turnindir{ex03}
\exnumber{03}
\exfiles{talk.md slides/}
\exauthorize{un éditeur de texte, un outil de présentation}
\makeheaderfiles

Construisez un talk de vingt minutes :

\begin{itemize}
  \item 3 minutes : le problème ;
  \item 5 minutes : le modèle en trois familles ;
  \item 6 minutes : la boucle et un cas nf\_tables ;
  \item 3 minutes : résultats, patch gap et limites ;
  \item 3 minutes : ce que l'auditeur peut réutiliser demain.
\end{itemize}

Dans \texttt{talk.md}, écrivez les notes orales, pas seulement les puces.
Chaque slide doit avoir une seule idée et une preuve visuelle. Le patch gap
doit être montré comme une chronologie sourcée, pas comme une opinion.

\chapter{Exercise 04}
\extitle{Q\&A et fact-checking}
\turnindir{ex04}
\exnumber{04}
\exfiles{qa.md}
\exauthorize{un éditeur de texte}
\makeheaderfiles

Préparez dix questions difficiles et leurs réponses. Incluez au moins :

\begin{enumerate}
  \item « Pourquoi votre classifieur n'est-il pas circulaire ? »
  \item « Combien de faux positifs sur un vrai noyau ? »
  \item « Quelle est la différence avec un simple grep ? »
  \item « Pourquoi ne pas utiliser un LLM ? »
  \item « Votre méthode marche-t-elle sur du code obfusqué ? »
  \item « Quelle CVE le papier a-t-il réellement prédite ? »
  \item « Qu'est-ce qui invaliderait votre thèse ? »
  \item « Un correctif incomplet est-il une nouvelle classe de bug ? »
  \item « Pourquoi un patch d'urgence n'est-il pas une preuve de
        correction ? »
  \item « Qui vérifie la version de V8 réellement embarquée dans un
        navigateur mobile ? »
\end{enumerate}

Pour chaque réponse, donnez la source ou l'expérience qui la soutient. Si
vous ne savez pas, écrivez « je ne sais pas » et la question à poser à
l'auteur.
