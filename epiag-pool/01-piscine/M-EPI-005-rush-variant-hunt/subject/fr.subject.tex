\chapter{Règles}

\begin{itemize}
  \item Durée : une journée, en équipe de deux ou trois.
  \item Sujet libre dans un sous-système que vous pouvez lire : nf\_tables,
        eBPF, io\_uring, ou un projet utilisateur.
  \item Le correctif choisi doit être public, petit (moins de cinquante
        lignes ajoutées) et documenté par un CVE ou un avis de sécurité.
  \item Aucun exploit, aucun test sur une cible réelle, aucun déni de
        service.
  \item Le rapport doit contenir toutes les commandes nécessaires pour
        refaire l'analyse.
\end{itemize}

\chapter{Objectif}

À la fin du rush, vous devez pouvoir dire :

\begin{quote}
« Voici un correctif. Voici l'hypothèse qu'il encode. Voici une fonction
voisine qui partage cette hypothèse sans la vérifier. Voici pourquoi ce
n'est peut-être pas un bug, et voici le test qui le confirmerait ou
l'infirmerait. »
\end{quote}

Le résultat peut être un faux positif. Un faux positif bien argumenté vaut
mieux qu'un « twin » inventé.

\chapter{Partie A --- Cadrage}

Avant de lire le code, remplissez une fiche de cadrage d'une page :

\begin{enumerate}
  \item \textbf{Cible} : projet, fichier, fonction, commit.
  \item \textbf{CVE ou avis} : identifiant, date, score CVSS.
  \item \textbf{Hypothèse initiale} : ce que le correctif suppose vrai.
  \item \textbf{Périmètre} : ce que vous allez lire, et ce que vous
        n'allez pas lire.
  \item \textbf{Critère d'arrêt} : quand déciderez-vous que le candidat
        est un faux positif ?
\end{enumerate}

Le cadrage est validé par un pair avant de continuer. Un cadrage trop large
est refusé.

\chapter{Partie B --- Analyse}

Appliquez la boucle :

\begin{enumerate}
  \item \textbf{Extraire} : les lignes ajoutées et la fonction.
  \item \textbf{Paralléliser} : au moins cinq fonctions voisines, avec
        \texttt{grep} (et \texttt{ctags} si disponible).
  \item \textbf{Vérifier} : pour chaque twin, l'invariant partagé, le test
        manquant, et le statut.
  \item \textbf{Trier} : score selon la grille du papier.
\end{enumerate}

Livrables intermédiaires :

\begin{console}
queries/
|-- grep.txt
|-- find.txt
+-- notes.md
analysis.md
\end{console}

\chapter{Partie C --- Rapport et soutenance}

Le rapport final \texttt{variant-report.md} contient :

\begin{enumerate}
  \item un résumé de dix lignes ;
  \item le diff annoté ;
  \item la carte des twins ;
  \item le candidat retenu et son score ;
  \item les preuves (commandes, extraits, sources) ;
  \item les limites et les faux positifs écartés ;
  \item une conclusion : confirmer, infirmer, ou demander un test
        supplémentaire.
\end{enumerate}

La soutenance dure cinq minutes, suivie de cinq minutes de questions. Vous
devez montrer le diff, la requête qui trouve le twin, et le raisonnement qui
mène au verdict.
